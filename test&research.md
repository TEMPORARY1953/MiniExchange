# Тесты и исследования Mini Exchange

## Методика

Unit-тесты проверяют внешний API библиотеки через GoogleTest 1.17.0.
Google Benchmark 1.9.4 измеряет обработку пакетов заявок в Release.
Зависимости загружаются CMake с проверкой закреплённых SHA-256.

## Проверяемые свойства

- Пустой стакан, добавление непересекающихся BUY/SELL.
- Полное исполнение при равных ценах и сделка по цене resting-заявки.
- Лучшая цена важнее более раннего времени поступления.
- FIFO внутри цены, даже если ID поступают не по возрастанию.
- Частичное исполнение resting-заявки сохраняет её место в очереди.
- Остаток входящей заявки становится в стакан по её собственному лимиту.
- Проход через уровни и остановка на цене за пределами лимита.
- Правильный порядок снимка; изменение копии не влияет на стакан.
- Нулевые и отрицательные поля, неверная сторона, повторный ID до и после исполнения.
- Ошибки валидации не изменяют стакан и не резервируют ID.
- Максимальные значения ID, цены и количества без переполнения при сопоставлении.

Семь сценариев сопоставления параметризованы для обоих направлений входящей заявки.

## Бенчмарк

| Сценарий | Работа за одну итерацию | Число входящих заявок |
| --- | --- | ---: |
| `BM_InsertNonCrossing/N` | N покупок на 32 ценовых уровнях, без сделок | N |
| `BM_MatchPairs/N` | N пар: продажа 10 единиц по 100, покупка по 101 | 2N |
| `BM_SweepPriceLevels/N` | N продаж на 32 уровнях + покупка, оставляющая 1 единицу | N + 1 |

В каждом сценарии `N = 128` и `4096`. Одна итерация создаёт новый стакан и
полностью уничтожает его: выделение и освобождение памяти, проверка и учёт ID,
сопоставление и создание вектора сделок включены в измерение. Ввод/вывод и
получение снимков не измеряются. Данные детерминированы; RNG не используется.
Размер стакана и набора ID ограничен размером пакета в каждой итерации.
`DoNotOptimize` и `ClobberMemory` препятствуют удалению работы оптимизатором.

Google Benchmark выводит `Time` (реальное время пакета), `CPU` (процессорное время
пакета), число итераций и `items_per_second` (входящие заявки/с).
Время пакета нельзя интерпретировать как задержку одной заявки.
Пропускная способность не равна количеству сделок/с: пары учитывают обе заявки,
проход учитывает N + 1 входящую заявку, а не число отдельных исполнений.

Команды воспроизведения:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel 2
ctest --test-dir build -C Release --output-on-failure --no-tests=error
cmake --build build --config Release --target run_benchmarks
```

Три повторения, минимум 0,1 с на замер. Для серьёзного сравнения нужны одинаковые
компилятор, настройки, машина и нагрузка, более долгие измерения и несколько запусков.
Shared runners GitHub Actions дают изменчивые результаты; пороги производительности
не установлены. Это учебный замер общей обработки, не измерение биржевой tail latency.

пока не проверены; разбор YAML не является запуском GitHub Actions.
