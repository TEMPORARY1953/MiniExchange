# Mini Exchange: инструкции для Codex

## Назначение и структура

Учебный локальный симулятор криптовалютной биржи. Конечная цель — собственный
биржевой движок на C++17, торговый веб-интерфейс для BTC/USD, виртуальные счета
с проверкой и резервированием средств, моделирование участников и торговые боты
с простыми стратегиями и сравнением результатов. Движок должен поддерживать
лимитные и рыночные BUY/SELL, приоритет цены и FIFO, полное и частичное исполнение,
отмену активных заявок и обновление стакана. Терминал должен показывать стакан,
историю сделок и график цены, позволять создавать и отменять заявки.
Реальные биржевые API и настоящие денежные операции не требуются.

Сейчас реализован только однопоточный Matching Engine одного инструмента:
лимитные BUY/SELL по приоритету цены и FIFO, полное и частичное исполнение,
снимки стакана, консольный пример и инфраструктура первого ДЗ. Backend,
веб-интерфейс, рыночные заявки, отмена, счета и боты пока не реализованы.
Требования к конечной версии описаны в `README.md`; их описание не разрешает
добавлять реализацию без отдельного задания пользователя.

- `include/mini_exchange/` — публичные структуры и интерфейс библиотеки.
- `src/` — независимое ядро без I/O, сети и UI.
- `app/` — консольный пример, только вызывает ядро и выводит данные.
- `tests/` — unit-тесты GoogleTest.
- `benchmarks/` — замеры Google Benchmark.
- `.github/workflows/ci.yml` — сборка, тесты, бенчмарк, Doxygen и Pages.
- `Doxyfile`, `README.md`, `Pipeline.md`, `test&research.md` — документация.
- `hw.pdf` — приоритетный источник требований домашнего задания.

## Команды из корня проекта

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel 2
cmake --build build --config Release --target run_demo
ctest --test-dir build -C Release --output-on-failure --no-tests=error
cmake --build build --config Release --target run_benchmarks
cmake -S . -B build-docs -DBUILD_TESTING=OFF -DMINI_EXCHANGE_BUILD_BENCHMARKS=OFF -DMINI_EXCHANGE_BUILD_DOCS=ON
cmake --build build-docs --target docs
```

На Windows подходит генератор `-G "Visual Studio 17 2022" -A x64`.
Doxygen HTML находится в `build-docs/docs/html`. Для первой полной конфигурации
нужен доступ к GitHub для загрузки закреплённых зависимостей.

## Стиль и правила

- Только стандарт C++17, без расширений компилятора и лишних зависимостей.
- Отступ 4 пробела; фигурная скобка в строке объявления; `#pragma once` в заголовках.
- Типы — `PascalCase`, функции и переменные — `snake_case`, поля класса — с суффиксом `_`.
- Использовать RAII и стандартные контейнеры, не добавлять ручное управление памятью.
- Публичный API документировать Doxygen; комментарии объясняют существенные решения.
- Цены в целых тиках и количество в целых единицах; не использовать `double` для цены.
- Сохранять правила: сделка по цене resting-заявки, FIFO по порядку вызовов,
  уникальные за жизнь стакана ID, проверка данных до сопоставления.
- Не связывать ядро с консолью. Будущий интерфейс должен оставаться отдельным адаптером.
- Не добавлять HTTP API, frontend, биржевые подключения, базы данных или отмену заявок
  без явного нового задания пользователя.

## Проверки и ограничения

- Перед завершением работы обязательно собрать проект и запустить CTest.
  Для изменений matching добавить или обновить содержательные тесты.
- При изменении ядра или бенчмарка запустить `run_benchmarks` в Release.
- При изменении публичного API или документации собрать цель `docs`.
- Не менять CI/CD без необходимости для текущего задания. Сохранять автоматические
  сборку, тесты, бенчмарк и документацию при push; деплой — из основной ветки.
- Не выдавать локальный запуск за успешный CI. Указывать реальные результаты,
  состояние публикации и непроверенные платформы в `test&research.md`.
- Не добавлять в Git каталоги сборки, `.tools/`, скачанные зависимости и сгенерированный HTML.
- Не менять `hw.pdf`, не публиковать секреты и не ослаблять тесты ради зелёного CI.
