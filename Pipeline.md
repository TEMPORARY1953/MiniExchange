# Обработка заявки в Mini Exchange

## 1. Поступление

Вызывающий код передаёт `Order{id, side, price, quantity}` в `OrderBook::add_order()`.
Один объект стакана соответствует одному инструменту. Время поступления определяется
порядком вызовов: ID и системное время не определяют FIFO.

## 2. Проверка

До сопоставления проверяются положительные ID, цена и количество, допустимость стороны
и уникальность ID за всю жизнь этого стакана. Ошибка вызывает `std::invalid_argument`
без изменения стакана. ID невалидной заявки не резервируется.
ID валидной принятой заявки сохраняется в `used_ids_`, даже после полного исполнения.

## 3. Поиск встречной заявки

- Для `BUY` выбирается минимальная цена среди `SELL` (`asks_.begin()`).
- Для `SELL` выбирается максимальная цена среди `BUY` (`bids_.begin()`).
- В очереди лучшего уровня выбирается первая заявка (`deque::front()`).

Покупка пересекает стакан, если её лимит **не ниже** лучшей продажи.
Продажа пересекает стакан, если её лимит **не выше** лучшей покупки.
Если лучшая встречная цена не подходит, остальные цены тоже не подходят: цикл завершается.

## 4. Исполнение

Исполняемое количество равно `min(incoming.quantity, resting.quantity)`.
В результирующий вектор добавляется `Trade` с ID покупки, ID продажи, количеством
и ценой **стоящей в стакане** заявки. Оба остатка уменьшаются на исполненное количество.
Сделки возвращаются в порядке фактического сопоставления.

## 5. Обновление встречной стороны

Полностью исполненная заявка удаляется из начала очереди. Опустевший ценовой уровень
удаляется из `map`. Частично исполненная заявка остаётся на прежнем месте в начале
очереди и сохраняет приоритет перед более поздними заявками той же цены.
Пока у входящей заявки есть остаток, поиск повторяется.

## 6. Сохранение остатка

Если встречных заявок больше нет или следующая цена не подходит, остаток входящей
заявки добавляется в конец очереди её **собственной лимитной цены**. Если остаток нулевой,
в стакан ничего не добавляется. Следовательно, после обработки валидной заявки
в стакане нет пересекающихся лучших покупки и продажи.

## 7. Возврат результата

Библиотека возвращает вектор сделок; историю и формат вывода определяет вызывающий код.
`orders(Side)` позволяет получить копию оставшихся заявок в порядке исполнения.
Приложение `app/main.cpp` печатает сделки и остатки. Для другого интерфейса можно
использовать те же методы без изменения алгоритма; сетевого слоя в проекте нет.

## Пример

До поступления покупки в стакане стоят продажи:

| Порядок поступления | ID | Цена | Количество |
| ---: | ---: | ---: | ---: |
| 1 | 1 | 100 | 5 |
| 2 | 2 | 100 | 4 |
| 3 | 3 | 101 | 6 |

Поступает `BUY #4`, цена 101, количество 12:

1. Исполняются 5 единиц против #1 по цене 100; остаток покупки — 7.
2. Исполняются 4 единицы против #2 по цене 100; остаток покупки — 3.
3. Исполняются 3 единицы против #3 по цене 101; покупка исполнена полностью.

Остаётся `SELL #3`, цена 101, количество 3. Пример одновременно показывает
ценовой приоритет, FIFO и частичное исполнение встречной заявки.
